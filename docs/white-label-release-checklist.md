# White-Label Release Checklist

Use this before publishing any client, franchise, reseller, or product-specific
site from shared infrastructure.

## Before build

- Confirm the public domain, brand name, support email, legal entity, and
  analytics property for this release.
- List every string that must not ship: agency name, other client names,
  internal domains, staging hostnames, old support emails, and shared product
  labels.
- Put those strings in `examples/forbidden-terms.template.txt` or your own
  `forbidden.txt`.
- Build the final production output. Scan the build output, not source files.

## Gate

```bash
node brand-leak-guard.mjs ./dist \
  --self clientsite.com \
  --terms-file forbidden.txt
```

The release passes only when the command exits `0` and prints `CLEAN`.

## After deploy

- Crawl the live sitemap and save the fetched HTML.
- Run the same forbidden-term file against the fetched responses.
- Check the 404 page, robots.txt, sitemap.xml, app manifest, RSS feeds, and
  JSON-LD separately.
- Record the release domain, commit, build command, and scan output in the
  deployment receipt.

## Common leak sources

- Shared footer links.
- Stale `mailto:` support addresses.
- Open Graph images generated by another brand.
- JSON-LD `Organization` blocks copied from a template.
- Error pages outside the main framework route.
- Source maps exposed in public builds.
- Customer portal, billing, or login links pointed at another brand.
